## What this decides

[ADR-0039](docs/adr/00039-private-access-layer-tailscale.md) — how a
`private` instance ([ADR-0038](docs/adr/00038-instance-exposure-modes.md))
becomes reachable over the **owner's own tailnet** without FluxVale
becoming a VPN operator.

- **Topology B** — one gateway pod per org, official `tailscale/tailscale`
  image, `TS_USERSPACE` (zero pod privileges; the operator's own posture),
  `TS_SERVE_CONFIG` mounted from a Secret the platform writes.
- **B1 routing** — one hostname `fv-<short-uuid>`, per-app ports at root
  path. B2 (Services, per-app hostnames) deferred with its cost stated.
- **`AccessProvider` boundary** — `provision_gateway` / `attach_instance` /
  `detach_instance` / `gateway_status` / `wake_intercept`; provider-opaque
  route keys, so a WireGuard swap needs no migration.
- **Billing** — per-gateway existence accrual (the `perform_settle`
  discipline), plus the spike's **must-fix**: `ComputeRunway` and
  `SweepZeroBalance` extended to gateways so an unfunded gateway suspends
  and runway stops over-estimating.
- **Wake** — the asleep serve target *is* the platform's wake endpoint;
  the request that finds `:running` flips the mount to the app Service.
  No data plane of ours, wake markers unchanged.
- **ADR-0038 §6 closed** (§7) — `:sleep` takes the row lock and adopts the
  current row before applying edge state, so an in-flight idle-sweep sleep
  cannot mint a wake-mode route after a toggle to private.

Adds ADR-0005 Am. 5 (the gateway lives outside the instance namespace and
never widens the edge entry) and ADR-0038 Am. 1 (the gap is closed).
